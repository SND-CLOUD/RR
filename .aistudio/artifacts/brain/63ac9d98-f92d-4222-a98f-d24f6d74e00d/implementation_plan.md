# نظام إدارة قطع الغيار الإلكترونية المتكامل في إجراءات الفحص والصيانة

تصور معماري وهندسي شامل لإدارة واختيار قطع الغيار الإلكترونية في قسم الصيانة عبر نافذة منبثقة ذكية ومستقلة، مع توحيد المعرفات والبيانات، ودعم قطع التشليح، والسماح بالرصيد السالب لتسيير العمل مع التدقيق المحاسبي.

---

## مراجعة المستخدم والقرارات المحورية (User Review & Critical Decisions)

> [!IMPORTANT]
> يرجى مراجعة النقاط الأساسية التالية التي تم تضمينها في هذا التصور لتأكيد ملاءمتها الكاملة لآلية العمل لديكم:

1. **توحيد بنية البيانات والمعرف الفريد عبر كافة الشاشات**:
   - توحيد معايير حفظ المجموعات والقطع عبر جميع المنافذ (شاشة الدليل، شاشة الشراء، والنافذة المنبثقة في الفحص والصيانة).
   - ضمان وجود المعرف الفريد `id`، واسم المجموعة `groupName`، ومعرف المجموعة `groupId`، ونوع الصنف `itemType: 'electronic_part'`، لمنع أي بيانات مشوهة أو ناقصة الربط.

2. **الشاشة المنبثقة الذكية (Modal / Drawer) بدلاً من حشو النماذج**:
   - إبقاء واجهات الفحص والصيانة خفيفة وسريعة عبر وضع مربع اختيار **"بدون قطع"** وزر **"تحديد / عرض القطع"** بجوار حقل التقرير الفني.
   - فتح نافذة متخصصة تحتوي على حقول اختيار المجموعة والقطعة، الكمية، الملاحظات، وجدول مؤقت مع خيارات التعديل والحذف.
   - دعم التفاعل باللمس: النقرة الأولى تفتح القائمة وتخفي لوحة المفاتيح للاختيار السريع، والنقرة الثانية تظهر لوحة المفاتيح لإدخال صنف جديد.

3. **الحفظ الفوري للمجموعات والقطع الجديدة في قاعدة البيانات**:
   - عند كتابة مجموعة جديدة أو قطعة إلكترونية جديدة في الشاشة المنبثقة، يتم اعتمادها فوراً في قاعدة البيانات المركزية (`electronic_part_groups` و `parts_catalog`) لتكون متاحة دائماً مستقبلاً، حتى وإن قام المستخدم بإلغاء إجراء الفحص لاحقاً.

4. **تكامل دورة العمل بين الفحص والصيانة**:
   - **في مرحلة الفحص**: تحديد احتياج الجهاز من القطع دون خصم أي رصيد مخزني، وتُحفظ القطع في بيانات الفحص المؤقتة ثم تُرحل مع بيانات الجهاز.
   - **في مرحلة الصيانة**: قراءة القطع المحددة في الفحص تلقائياً وإتاحة تعديلها أو حذفها أو إضافة غيرها.
   - **خيار "تشليح" في الصيانة**: مربع اختيار لكل قطعة؛ إذا تم تفعيله، **لا يتم خصم القطعة من رصيد المخزن ولا تُحتسب قيمتها ضمن نفقات الصيانة**، مع احتساب أجور الصيانة بشكل مستقل.
   - **الخصم الفعلي للمخزون**: يتم فقط عند الترحيل النهائي لإجراء الصيانة (الحالة 50 - جاهز للتسليم).

5. **دعم الرصيد السالب وتنبيه المشتريات المعلقة**:
   - الموافقة التامة على مقترحكم بالسماح بانخفاض رصيد القطعة إلى قيمة سالبة (مثال: `-1` أو `-2`) لعدم تعطيل تسليم وصيانة الأجهزة في حال تأخر إدخال فاتورة الشراء أو فك القطعة من جهاز متعثر.
   - تمييز القطع ذات الرصيد السالب بتنبيه لوني بارز: **"يجب إدخال فواتير القطع السالبة"** في جدول القطع وسجل المخزن لضمان الدقة المحاسبية.

## 1. نظرة عامة والمفهوم الأساسي (Overview & Core Concept)

### الهدف العام
فصل التعقيد الخاص بقطع الغيار الإلكترونية عن النماذج الرئيسية لقسم الصيانة عبر شاشة منبثقة تفاعلية ذكية، مع الحفاظ على تسلسل الإجراءات التشغيلية وضمان تدفق سلس للمعلومات من مرحلة الفحص المبدئي إلى مرحلة التنفيذ الفعلي في الصيانة.

### الفئات المستهدفة
* **مهندس الفحص**: يحدد العطل والقطع الإلكترونية اللازمة دون انشغال بالأرصدة المخزنية الحالية.
* **مهندس الصيانة**: يطّلع على ما طلبه الفحص، يركب القطع أو يستبدلها بقطع تشليح، ويخصم الفعلي عند اكتمال الإصلاح.
* **إدارة المحل والمحاسبة**: تتبع دقيق لنفقات القطع المستهلكة مقابل قطع التشليح، وتنبيهات فورية لتسوية الأرصدة السالبة.

## 2. تجربة المستخدم والتصميم المرئي (User Experience & Visual Design)

### مسار إجراء الفحص (Inspection Flow)
```
[ صفحة إجراء فحص ]
       │
       ├─► [☑ بدون قطع] (مفعل افتراضياً)
```

### مسار إجراء الصيانة (Maintenance Flow)
1. **التعرف التلقائي على حالة الفحص**:
   - إذا كان الجهاز مفحوصاً ومعه قطع مسجلة: يكون خيار "بدون قطع" غير مفعل تلقائياً، وتظهر علامة بعدد القطع الجاهزة.
   - إذا كان الجهاز بدون قطع: يظهر خيار "بدون قطع" مفعلاً.
2. **شاشة الصيانة المنبثقة**:
   - زر **"عرض / تعديل القطع"** يفتح النافذة مع جلب كافة القطع المدخلة في الفحص تلقائياً.
   - عمود وخيار **"تشليح"**:
     - مربع اختيار عند كل سطر.
     - عند تحديده: يتم إعفاء القطعة من الخصم المخزني، وتصبح تكلفتها 0$ في نفقات صيانة الجهاز.
3. **الاعتماد والترحيل النهائي**:
   - يتم خصم القطع غير المحددة كتشليح من رصيد المخزن (حتى لو نزل الرصيد إلى سالب).
   - احتساب تكاليف القطع وإضافتها لتقرير الصيانة وحساب الأرباح والخسائر.

### سلوك لوحة المفاتيح والقوائم الذكية
* **الضغطة الأولى**: فتح قائمة الخيارات المنسدلة فوراً مع إخفاء لوحة المفاتيح الافتراضية للجوال لتمكين المهندس من الاختيار السريع بإصبعه.
* **الضغطة الثانية**: تفعيل المؤشر وإظهار لوحة المفاتيح في حال رغب المهندس في كتابة كود صنف جديد غير مسجل في الدليل.

## 3. القرارات المعمارية والفنية (Key Product Decisions & Trade-Offs)

### القرار 1: توحيد المعرفات والبيانات
* **النهج**: إنشاء وحدة معيارية موحدة لإضافة المجموعات والقطع الإلكترونية تُستخدم عبر كافة الشاشات.
* **الأثر**: منع ظهور أي قطع بدون `groupId` أو بدون `itemType`، وتوحيد مسميات الأعمدة بين التخزين المحلي (SQLite) والتخزين السحابي (Firestore).

### القرار 2: عدم حشو واجهة الفحص والصيانة
* **النهج**: إبقاء الحقول في نافذة منبثقة مستقلة متكاملة.
* **الأثر**: سرعة وسلاسة تعبئة تقرير الفحص والصيانة للأجهزة التي لا تتطلب قطع غيار (وهي نسبة كبيرة من الأجهزة التي تحتاج فقط إعادة برمجة أو تنظيف أو لحام بسيط).

### القرار 3: دعم الرصيد المخزني السالب مع التنبيه البصري
* **النهج**: عند ترحيل الصيانة لقطعة رصيدها 0، يتم إنقاص الكمية لتصبح `-1`، مع وسم السجل بعلامة `hasNegativeStock: true`.
* **الأثر**: استمرار تسليم الأجهزة دون توقف للورشة، وظهور شريط تنبيه ملون في شاشات الجرد وفواتير الشراء: *"تنبيه: توجد قطع ذات رصيد سالب يلزم إدخال فواتير مشترياتها"*.

### بنية كائن القطعة داخل حركة الصيانة (`DevicePartUsageItem`):
```typescript
interface DevicePartUsageItem {
  id: string;               // معرف فريد
  partId: string;           // معرف القطعة في الدليل
  partName: string;         // كود / اسم القطعة (مثال: TPS54294)
  groupId: string;          // معرف المجموعة
  groupName: string;        // اسم المجموعة (مثال: Ubiquiti Power)
  quantity: number;         // العدد المستخدم (افتراضي 1)
  unitCost: number;         // سعر الشراء / التكلفة
  unitSalePrice: number;    // سعر البيع المعتمد
  isScrap: boolean;         // خيار "تشليح" (صحيح = لا يخصم ولا يحتسب كنفقات)
  notes?: string;           // ملاحظات المهندس
  addedInStage: 'inspection' | 'maintenance'; // المرحلة التي أضيفت فيها
}
```
